LegoSim: a first-person LEGO building simulator — technical report

An engine that executes building actions on LEGO models (connector and geometric rules, preconditions, refusal codes), a planner that turns LDraw models and reviewed instruction recipes into action lists, a mistake generator, and a renderer that turns each executed action into first-person rendered video of a person building, with per-frame labels and controllable scenes.

Scenarios on real LEGO sets. Open the scenario report for fresh JSON-driven episodes with visible hands on sets from this report. Coverage, unresolved outcomes, missing capabilities and separate validation results are derived from run artifacts.

Shared-pipeline evaluation evidence. The generalization gallery preserves the recorded assembly and scene variations, action traces, observations, failures and representative videos. Its outcomes belong to the included original source freeze; packaging adds no new validation. The implementation audit distinguishes shared rules, task data, reusable initializers and remaining fitted demonstrations; the configuration example adds a task without a new motion branch.

The 19 reviewed clips and historical model benchmark below remain historical evidence. New object-motion videos do not certify human contact. Strict human attempts and independent validation results are disclosed separately; engine completion alone does not establish motion feasibility or official instruction order.

3. How it works

From instructions to labelled video. Instructions (LDraw model and reviewed booklet recipe) → planner (action list) → engine (executes each action: checks the precondition, applies the effect or refuses with a code) → motion layer (timed hand, part and head motion toward each state the engine produced) → renderer (Blender, a seated human, head-mounted camera) → video and labels. Mistakes are edits of the action list; scene factors are a settings record read by the renderer.

3.1 World state

partsid, LDraw shape, colour, pose (4×4, LDraw units, −y up), and where it is: table, hand:L/R, assembly (built in), resting (on the model, not clicked in), bag:k (in closed bag k)
connectionslist of engagements: (part a, connector i) male ↔ (part b, connector j) female, with insertion depth; a model is a connected component of this graph
handsL and R: empty, a part id, model:<pid> (a held model) or tool:separator
alsotools (the brick separator and where it is), bags (open or closed, their parts), supports (which built part a resting part lies on), placement order (when each part was built in)
ground truthfrom the official model: allowed box overlaps, and trusted links for joints without connector data (accepted only at the exact official relative pose, within 0.6 LDU / 0.001)

3.2 Connectors

Every part carries connector points from the LDCad snap library (studs, anti-stud tubes, pins, holes, axles, bars, clips): position, axis, gender, and a cross-section profile (e.g. round, radius 6, length 4 LDU). A male and a female connector are compatible if a radius class matches (an axle also fits a round hole). They engage when their axes are parallel (|cos| ≥ 0.995), at most 0.6 LDU apart sideways, and overlap along the axis; the overlap is the insertion depth, seat = min(1, depth / 4 LDU). A short connector (≤ 4 LDU, a stud) holds one partner; long ones (bars, pins) pass through several parts. Connectors can be addressed by index or by grid address (face, column, row) in stud pitches (20 LDU).

3.3 Placing a part: mate

The pose of the held part is solved in closed form from the two connector frames (origin = connector start, z = axis, x = a fixed perpendicular): a_m = flip·a_f, p_f = p_m − slide·a_m, x_m = R(a_m, turn)·x_f. Then, in order:

  1. a placement within 0.6 LDU / 0.1 of a planned part's official pose takes that exact pose (source models store slightly non-orthonormal rotations);
  2. a misalignment within 2.0 LDU / 6° self-aligns when pressed; a turn within 8° of the 90° stud grid snaps to it;
  3. if anything engages: refused if the part would interpenetrate another (COLLISION) or could not have been pushed in along the joint axis from a joint length + 1 LDU out (APPROACH_BLOCKED; stud-length joints, exempt at official poses); else mated, recording every engagement at that pose;
  4. if nothing engages: the part backs off along the joint to where the connector tips touch. If that direction is upward it rests there, at the lowest height where it touches nothing (on a neighbour's top if higher, up to 24 LDU); otherwise nothing holds it and it falls onto the table beside the model.

affordances(part) enumerates every (connector, target connector, turn, flip, slide) that engages without interpenetration (poses solved in one batch, duplicates merged).

3.5 From instructions to an action list

The model file is read step by step (sub-models expanded; part definitions embedded in the file become parts; a flexible hose drawn as segments becomes one part). A reviewed instruction recipe takes precedence over file order and explicitly builds the booklet’s callouts before attaching them. The Dracaena recipe maps printed steps 36–42 to five callout subassemblies. Each recipe records the source PDF, page numbers and checked model fingerprint. For models without a reviewed recipe, groups are inferred from LDraw order and connectivity; this does not establish agreement with the official booklet. In that fallback, a part that touches nothing built so far starts a group, made on a free spot on the table (the first spot where its whole finished footprint clears everything else) — a sub-build. When a later part links two groups, the later one is attached to the earlier when its own run of parts ends; a sub-build still on the table at the end is attached to whatever it has a joint with (separate objects, like a figure beside a car, stay separate). Every placement becomes mate on the deepest real connector engagement with the part it goes onto, if that reproduces the official pose exactly; otherwise (no connector data) a pose-level place accepted through a trusted link. Optionally parts start in numbered bags (contiguous step runs, ~40 parts a bag) with open_bag inserted before each bag's first part. Replay checks the resulting structure against the official model.

3.6 Progress tracking

After any action every built part is compared with the official model, after aligning each separate model on one of its parts: correct, misplaced, not pressed down (right place, up to 4 LDU high), resting, foreign (not in the plan: wrong part or colour), loose. Complete = all correct, in as many pieces as the official model.

3.7 Mistakes and fixes

A mistake is a different choice of mate parameters at one placement, taken from what is feasible at that moment (affordances), so it is accepted wherever it is physically possible; a candidate that ends at the correct pose anyway (symmetric part, a gap that self-seats) is not a mistake. The rest of the build then runs through the engine unchanged, which decides what follows (continues, or a later step is refused). A fix is notice + taking the part off (fingers, or the separator where fingers can't grip; parts locking it in come off first and go back afterwards) + the correct action, after any delay. The daily-demo generator preserves the requested mistake kind and optional part identity; it reports an unavailable case instead of substituting a different action. Recovery is checked against the normal stage's final poses and connections.

3.8 Motion

Each accepted action becomes phases (e.g. pick: reach 0.6 s, grasp 0.3 s; mate: lift 0.25, carry 0.5 + 1.2 s per metre, align 0.3, press 0.35, release 0.2, retract 0.5), eased, scaled by a per-action speed factor (log-normal, σ 0.18). Hand targets are refined against individual finger contact targets with bounded wrist and finger kinematics. The head follows the gaze target through a critically damped second-order system (ω = 7.0 rad/s). Styled runs add, at set rates: misaligned landings that slide into place (35%), visual search (35% × loose parts / 20), re-grips when a part must be tipped over, missed grasps (4%), hesitation over look-alikes (25%), looking up at a new step (8%), glances at the booklet. Hand identity follows the engine's ownership of the part; the free hand can support it during regripping.

3.9 Hands and grasps

For sources that use contact fitting, grasp proposals balance approach, reach, comfort and visibility. Explicit palmar-pad contacts are selected on the part surface and retained in its local coordinates during carrying and rotation. The renderer checks intended contact, sampled finger penetration, arm reach and wrist limits, and tries alternative palm orientations when needed. It keeps engine-produced part poses fixed.

        """Remove a built or supported unseated part with the held tool.

        The other hand receives it. Built parts must have one release direction
        that frees every joint. An unseated part keeps its resting provenance:
        removing it clears a support edge, without inventing an attachment.
        Actual tool engagement and continuous support are motion-layer checks.
        """
        tag = f"pry {pid}"
        t = self.tools.get(name)
        if t is None or not t["where"].startswith("hand:"):
            return self._done(Result(False, tag, f"the {name} is not held"))
        other = "L" if t["where"][-1] == "R" else "R"
        if self.hands[other] is not None:
            return self._done(Result(False, tag, f"hand {other} is holding {self.hands[other]}"))
        p = self.parts.get(pid)
        if p is None or p.where not in ("assembly", "resting"):
            return self._done(Result(False, tag, "part is not attached"))
        if p.where == "resting":
            supports = getattr(self, "supports", [])
            hosts = sorted({on for q, on in supports if q == pid and on != pid
                            and on in self.parts and self.parts[on].where in ("assembly", "resting")})
            if not hosts:
                return self._done(Result(False, tag, "resting part has no live support", code="NOT_SUPPORTED"))
            if any(on == pid and q in self.parts and self.parts[q].where == "resting" for q, on in supports):
                return self._done(Result(False, tag, "blocked by parts resting on it: remove those first", code="BLOCKED"))
            if any(pid in (c.a, c.b) for c in self.conns):
                return self._done(Result(False, tag, "resting part has inconsistent attached connections", code="REJECTED"))
            self.supports = [edge for edge in supports if edge[0] != pid]
            p.where = f"hand:{other}"; self.hands[other] = pid
            return self._done(Result(True, tag, effect={"held_by": other, "direction": [0.0, -1.0, 0.0],
                                                       "from": "resting", "support_released": hosts}))
        d, blockers = self.removal_dir(pid)
        if d is None:
            return self._done(Result(False, tag, f"blocked by {sorted(blockers)}: no direction frees every joint"))
